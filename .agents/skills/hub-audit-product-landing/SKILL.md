# Skill: Audit Product Landings & SEO

This skill provides a comprehensive auditing and verification procedure for all **Pastel-Tech Product Landing Pages** (`product` block in `src/content/projects/{es,en}/*.md`), ensuring complete alignment between upstream source repositories and the live showcase at `<slug>.ana-catalina.com`.

## When to Use This Skill
- Before releasing portfolio updates or committing new project entries.
- When verifying that product landing copy (`tagline`, `intro`, `features`, `codeSnippets`) hasn't drifted from upstream software changes.
- To audit SEO health (title length, meta description length, canonical URLs, structured data, zero flags).
- To detect obsolete binary names, missing CLI commands, or restrictive phrasing (e.g., claiming "only CLI" when Desktop support exists).

---

## 1. Automated Audit Execution

Run the dedicated landing audit tool from the project root:

```powershell
npm run audit:landings
```

Or execute directly via Node:

```powershell
node .agents/skills/hub-audit-product-landing/scripts/audit-product-landings.mjs
```

---

## 2. Core Audit Dimensions

### A. SEO & SERP Optimization
1. **Title Length (`<title>{title} — {product.tagline}</title>`):**
   - Optimal length: **30–65 characters**.
   - Beyond 70 characters, search engines (Google, Bing) truncate the title in search result snippets.
2. **Meta Description (`<meta name="description" content={product.intro} />`):**
   - Optimal length: **100–160 characters**.
   - Must concisely communicate the user value proposition without generic fluff or internal planning jargon.
3. **Structured Data & Schema.org:**
   - Server-side JSON-LD `@type: SoftwareApplication` is automatically generated by `src/layouts/ProductLayout.astro`.
   - Requires valid `platforms` list to map to `operatingSystem`.
4. **Canonical & Hreflang URLs:**
   - Canonical points to dedicated subdomain (`https://<slug>.ana-catalina.com/` for ES, `.../en` for EN).
   - Must have symmetric bilingual parity across Spanish and English files.
5. **Zero Flags Policy:**
   - Absolutely NO country flag emojis anywhere in SEO title, meta descriptions, or content.

### B. Upstream Binary & CLI Command Alignment
1. **Binary Exports Verification:**
   - Inspects the upstream repository's manifest (`package.json` `bin` field, `Cargo.toml` `[[bin]]`, etc.).
   - Confirms that `codeSnippets` demonstrate the actual modern binaries and subcommands available (e.g. `ami` and `amiga-ia-setup`).
2. **Host Surface & Platform Parity:**
   - Cross-checks `product.platforms` against the application's true runtime capabilities.
   - Detects obsolete restrictive phrases (e.g., claiming "solo para la terminal / only CLI" when Desktop or GUI support exists).

### C. Content Completeness & Design Tokens
1. **Features Matrix:**
   - Minimum of 3 features per product landing.
   - Every `icon` must strictly match an official export from `lucide-static`.
2. **Download & Interactive CTAs:**
   - Mandatory `downloadUrl` and `downloadLabel`.
3. **FAQ Section:**
   - Recommended minimum of 2 FAQ pairs per product page to enrich search snippet context and user clarity.

---

## 3. Remediation Workflow

When the audit flags warnings or issues:
1. Open both `src/content/projects/es/<slug>.md` and `src/content/projects/en/<slug>.md`.
2. Adjust `tagline` or `intro` to bring lengths within the optimal SEO range (30-65 chars for title, 100-160 chars for intro).
3. Synchronize `codeSnippets` with the latest CLI commands from the upstream repository.
4. Re-run `npm run audit:landings` until all critical issues and semantic drift warnings are resolved.
5. Execute full quality gates:
   ```powershell
   npm run lint; npm run type-check; npm test; npm run build
   ```
